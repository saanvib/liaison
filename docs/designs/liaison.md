## Problem Statement
Customers of a regulated life-science product company ask questions (datasheets, IFU, validation, usage) that a bot can answer from documents most of the time. The risky answers (off-label use, clinical use of an RUO product, comparative claims, pricing, roadmap, patient data) must never leave the company unchecked, and the questions the docs can't answer need a human expert. Liaison is an agent network, registered on Agentverse and reachable through ASI:One, that answers from company docs with citations, escalates the rest to the right internal expert in Slack, and learns from approved expert answers.

## What Makes This Cool
The learning loop. An unknown question escalates, an expert answers in Slack, the Compliance Guard approves it, and the same question is answered instantly next time. The Guard is the differentiator: it checks the Vendor Agent's drafts and the experts' answers, so the knowledge base itself stays compliant.

## Constraints
- Hackathon, three people building in parallel against the frozen `contracts/` folder (GuardRequest/GuardVerdict, Escalation, ApprovedAnswer, IngestDocument; committed as 1973b92).
- Fetch.ai eligibility: at least one agent on Agentverse, Chat Protocol, usable through ASI:One, public GitHub repo, primary workflow works without a custom frontend. Judging weights: functionality 25%, Fetch.ai tech 20%, innovation 20%, real-world impact 20%, UX/presentation 15%. Rubrics vary by event, so check the event's own hackpack.
- Python + uAgents; Slack via Socket Mode.
- Docs are synthetic (no real vendor data).

## Premises
1. The demo's "whoa" is the learning loop.
2. The Guard is the differentiator and also gates the KB write path.
3. Closest existing thing is internal Slack Q&A bots (Glean/Guru); Liaison is customer-facing with compliance as the product.
4. A demo-grade slice is enough: synthetic docs, a ~40-question labeled Guard test set, and a repeat question that visibly answers faster.
5. For judging, the live ASI:One path matters more than extra features.

## Approaches Considered
- **A: Thin thread** (only the Vendor Agent on Agentverse; Guard and Router in-process). Rejected: weak Fetch.ai usage score and it discards the frozen contract.
- **C: Guard as a public product** (B plus a standalone discoverable Guard). Rejected for now: extra scope that could dilute the learning-loop story. Revisit as a stretch goal or demo fallback.
- **B: Three agents, demo-first** (chosen, below).

## Recommended Approach
**B: Three agents, demo-first build order.** The Vendor Agent, Compliance Guard and Router are each registered on Agentverse and speak the Chat Protocol. Every hop uses the frozen contract messages. Rationale: the learning loop is the agreed "whoa", and three agents map directly to the Fetch.ai-tech and functionality criteria.

- Build the end-to-end loop first, against stubs (stub Guard always approves, stub Router posts a fake escalation), before polishing any one agent.
- Vendor Agent: retrieval over uploaded docs with citations and a confidence score; KB is a JSON file plus embeddings; low confidence or non-approved verdict creates an Escalation.
- Router + Slack: topic classification (R&D, QA/RA, engineering, sales ops), posts to expert channels, captures thread replies, sends them through the Guard, approve/edit buttons for `needs_review`, reroutes pricing to sales, sends `ApprovedAnswer` back.
- Guard: rules (pricing, patient data), policy file, LLM judge, grounding check; ~40-question labeled set with precision/recall per category.
- Async follow-up: when the expert's answer is approved, the asker gets a follow-up message in the ASI:One chat.
- Fallback: if Agentverse messaging is flaky by the midpoint, collapse to Approach A.

## Open Questions
- Which hackathon and which rubric applies (weights and eligibility differ by event)?
- How does the Vendor Agent decide "same question as before" (paraphrase matching threshold)? This is the heart of the instant-repeat demo.
- Which LLM powers the judge and the Vendor Agent's drafting, and who holds the API key budget?
- How should an async expert answer reach an ASI:One user who has left the chat session?
- The regulatory framing (RUO vs off-label rules) is unverified against FDA/EMA guidance; the Guard policy file should cite its source.

## Success Criteria
- ASI:One returns a cited answer from the synthetic docs.
- An unknown question creates an Escalation that appears in Slack; the expert's reply becomes an `ApprovedAnswer`.
- The same question, asked again, is answered from the KB with no escalation.
- A prompt for each blocker category (RUO clinical use, off-label, comparative, pricing, roadmap, patient data) gets a blocked or rerouted verdict with a reason.
- The Guard eval runs standalone and prints precision/recall per category.
- All three agents are visible on Agentverse and the repo is public.

## Distribution Plan
Public GitHub repo (saanvib/liaison). Agents deployed on Agentverse (mailbox or hosted); judges reach them via a shared ASI:One chat URL. A short demo video of the full loop. No separate CI/CD needed for the hackathon.
